# 01 실험 경과

시각은 서버 기준(KST)이다. 파이프라인 시작과 종료 기록은 [supervisor.log](../logs/supervisor.log)에 있다.

## 1. 3개 모델 구성 검증 (11-04 오전)

학습 전 분리된 3개 모델이 설계대로 구성됐는지 먼저 확인했다. 스크립트는 [code/verify](../code/verify), 결과는 [report-final.json](../results/verify/report-final.json)이다.

- 직접 만든 검사 137개가 모두 통과했다. 저장소 테스트는 215개 통과, 4개 건너뜀이다.
- 실제 state pair 12개로 forward, 기울기, 작은 배치 과적합, 저장·복원, GPU 1개와 2-GPU DDP를 확인했다.
- README의 파라미터 표는 `skip_mode=identity` 기준인데 실제 설정은 `affine`이었다. 실측값은 `residual_mlp` 349,440개, `transformer` 457,216개, `mlp_context` 539,584개이다.
- 이 단계는 동작 확인이다. 전체 데이터 학습 품질과 J&F는 다음 단계에서 측정했다.

## 2. 민감도와 구조 후보 (11-04 오후)

어떤 오차가 J&F를 깎는지 재고, 공간·포인터 후보를 학습했다.

- 포인터 번역 오차의 J&F 영향은 작았다(LVOS -0.06, MOSE -0.13).
- 손실의 대부분은 영상 끝까지 남는 조건부 기록의 공간 오차에서 나왔다. 조건부 기록만 Base+ 값으로 바꾸면 `legacy`가 MOSE 64.46, LVOS 75.28까지 올라갔다.
- 공간 MSE가 낮은 모델이 J&F도 높은 것은 아니었다.

실험이 SSH 연결과 무관하게 돌도록 감독 스크립트와 재개 구조를 넣었다. 이때 torch 2.11과 SAM2 `_C.so`의 조합에서 GPU 메모리 누수를 발견해 평가를 torch 2.8로 옮겼다.

## 3. 비교군 측정 (11-04 저녁)

OLV, 프롬프트만, 마지막 마스크만, Direct Copy, Replay, Moment-Matched를 MOSE dev와 LVOS val에서 측정했다.

- OLV는 네 데이터셋 모두에서 번역과 같거나 높았고, 유의한 곳은 M3-VOS였다.
- OLV는 Small이 전환 시점에 틀리면 그 오류를 고정하는 약점이 있다.
- 비용은 번역이 훨씬 유리했다. 시간은 OLV의 약 30분의 1이다. 전달 데이터 크기만 OLV가 작다(0.12 MB 대 8.41 MB).

이 시점에 연구 방향을 분명히 했다. 전환의 필요성은 판단 대상이 아니고, OLV는 비교군이며, 목표는 전환 모델의 정확도다. 이후 정확도 실험을 대기열 앞으로 옮겼다.

## 4. 원인 분석 (11-04 밤)

번역 출력의 에너지가 목표의 76~82%로 줄어 있었다. 이득 보정, 조건부 기록 교체, 오차 분해를 실험했다.

- 대비를 1.1배 키우는 것만으로 MOSE +2.05, LVOS +2.51이 올랐다.
- 조건부 기록 오차를 나누면 손실은 대비 축소분(-6.86, MOSE)과 물체 근처, 고주파 성분에 몰려 있었다. 먼 영역과 저주파는 거의 영향이 없었다.
- `legacy`의 object score는 Base+보다 평균 1.12 낮았다. 물체가 사라졌다고 판단한 프레임의 손실이 여기서 나온다.

## 5. 파인튜닝 (11-04 밤 ~ 11-05 새벽)

상태 MSE 대신, 번역된 기억을 고정된 Base+ memory attention과 mask decoder에 통과시켜 실제 Base+ 상태의 출력과 맞추도록 학습했다. 과거 RGB는 쓰지 않고 전환 이후 프레임은 학습 데이터로만 쓴다.

- 3,000스텝 중간 모델이 MOSE 63.44로 당시 최고 번역 성능을 냈다.
- 평가 코드가 256개 항목의 IoU로 고른 `model.pt`를 쓰고 있어 조기 스텝에 고정된 것을 발견했다. 이 값은 항목 하나에 0.004씩 움직이는 잡음이라, 이후 평가는 마지막 가중치를 쓴다.
- 마지막 가중치 `e2e_ctx`는 MOSE 64.17, `legacy` 대비 +3.37 [+1.60, +5.29]이다.

## 6. 기록 고정과 3라운드 (11-05 새벽 ~ 오전)

- 전환 몇 프레임 뒤 Base+가 직접 만든 기록을 조건부 칸에 남기는 기록 고정을 시험했다. 1~7프레임 범위가 좋았고 그 안의 우열은 구분되지 않았다.
- 조건부 기록만 읽는 시나리오, 긴 오프셋, LVOS 표본 증가를 넣은 3라운드를 학습했다.
- LVOS val을 이미 한 번 봤기 때문에, 이후 후보 선택은 MOSE dev와 LVOS dev로만 했다.
- `transformer`도 같은 파인튜닝을 거치게 해서 세 구조를 같은 조건으로 비교했다.

## 7. 데이터 의존성 점검 (11-05 오전)

파인튜닝이 데이터셋에 맞춰진 것은 아닌지 확인했다. 영상 ID는 분리돼 있었지만 같은 장면을 공유하는 영상이 있었다. 같은 장면 제외 재계산과 학습 영상 J&F 비교를 추가했다. 자세한 내용은 [05 데이터 분리와 과적합](05_data_separation.md)에 있다.

프록시 측정에서는 학습 영상이 더 좋게 나왔지만 J&F에서는 차이가 없었다. 처음의 "실패 감소는 거의 학습 영상에서만 나타난다"는 해석은 J&F 결과로 수정했다.

## 8. 3라운드 판단과 최종 판정 (11-05 오후)

외부 데이터셋에서 2라운드와 3라운드를 직접 비교했고, 이득이 없어 권장 모델을 `e2e_ctx`로 정했다. 미리 정한 기준이다. `residual_mlp`, `transformer`의 2라운드 모델도 외부 데이터셋에서 평가해 세 구조를 판정했다.

## 9. 중단 (11-05 19:19)

판정에 필요 없는 저순위 작업을 요청에 따라 모두 중단했다. 중단 시점의 미완료 실행은 [07 한계와 남은 일](07_limits_and_open_items.md)에 있다.

## 10. 논문과의 비교 (11-05 저녁)

논문 평가 DB를 확인하는 과정에서 `legacy`가 논문 모델이 아니라는 것을 발견했다. 이전 판정의 `legacy` 대비 수치는 그대로 유효하지만 논문 모델과의 비교는 아니다. PUMaVOS는 논문 DB와 케이스 단위로 다시 비교했다.
